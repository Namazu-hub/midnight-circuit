# スマートフォン操作の改善（v4.0.1）

## 変更

- `dist/touch-input.mjs` に接触IDごとの入力管理を分離。二本指の移動＋ジャンプ、同じボタンを複数の指で触る場合も、残っている接触の入力を維持。
- 指を別のボタンへ滑らせると入力を切り替え、ボタン外では解除。documentのpointerup/cancel、capture喪失、touch終了、blur/pagehide、非表示化、モード変更、向きの変更で取り残された入力を解放。
- 操作パネルだけ文字選択・長押しメニュー・ドラッグを抑止。方向アイコンは選択可能な文字からCSS図形へ変更。ページ全体の拡大は禁止しない。
- 横向きのタッチ端末、または横幅1400px以下・高さ600px以下の横長画面では、プレイ中にゲーム専用表示。ステージ一覧・説明・フッターを隠し、ゲームの下に指で隠れない操作欄を配置。Fullscreen API非対応でも利用可能。
- safe-areaと動的viewport高に対応。回転時は一時停止し、入力とCanvasサイズを更新。タイトル／マップへ戻ると通常のページ表示へ復帰。
- ステージ、敵、修理、セーブキー、物理ロジックは変更しない。

## 検証

- `npm run check`: 12モジュールの構文、相対import、HTMLアセットを確認。
- `npm test`: 既存23件と入力9件の計32件が成功。全8コースの自動入力による到達、残機・フィーバー・ボス等の回帰検査を含む。
- 入力テストはEventTargetを用いたイベント単体テスト。実機タッチやSafariの再現ではない。
- ブラウザでの画面サイズ別確認は公開後に実施し、結果を追記する。
- iPhone Safari／Android Chrome実機、二本指の感触、ノッチ、ブラウザバー開閉、OSによるジェスチャー中断は未検証。

## 再確認手順

1. `tools/mobile-preview.html` または端末で通常ゲームを開く。
2. ステージ1を開始。左右を長押し・外へずらして離す。停止し、文字選択やコピー表示が出ないことを確認。
3. 移動を押しながらジャンプ・パルス。片方を離してももう片方が継続することを確認。
4. プレイ中に回転、一時停止、別タブへ移動、画面ロック後の復帰。入力が残らないことを確認。
5. 横向きでゲーム・左右・ジャンプ・パルス・一時停止が画面内に収まることを確認。
6. ステージ3で上段／下段も表示されること、タイトルへ戻るとマップを再び選べることを確認。

レイアウト検証ページは指定サイズのiframeで通常ゲームを読み込むだけです。通常と同じセーブを利用します。ゲーム内部の状態を変更するテスト専用機構はありません。
