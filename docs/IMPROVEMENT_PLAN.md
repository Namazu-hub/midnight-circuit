# 次段階の改善計画

今回、軽量化・新ステージ・新BGM・新機能は追加していない。

## 実機で基準を測る

iPhone SafariとAndroid Chromeで通常、縦移動、台車、フィーバーを同じ条件で計測する。機種、OS、画面サイズ、設定、音の有無、温度条件を記録。平均FPSだけでなくフレーム時間の中央値/p95、長いフレーム、メモリー増加、入力遅延、10分以上の連続プレイを調べる。計測APIの未対応をゼロとして扱わない。

## 負荷候補（すべて未実測の仮説）

| 候補 | 根拠と確認方法 |
| --- | --- |
| 光・影・立体文字 | フィーバーの多重描画、光沢、粒子。描画プロファイルで比較 |
| 背景の毎フレーム描画 | タイトル含め装飾を更新。静止部分のキャッシュ効果を測定 |
| 120Hz物理と配列走査 | 足場・敵等を複数ステップで走査。CPU時間を分けて測定 |
| HUD更新 | ループ中のDOM変更。値が同じフレームの費用を調べる |
| 保存 | JSON生成・同期localStorage。保存と長いフレームの相関を確認 |
| 音声合成 | BGMと撃破音のノード。音オン/オフと同時発音数で比較 |

距離による敵更新抑制や描画の絞り込みはすでに一部ある。最適化が全くないとは扱わない。原因未確定のまま物理レートや敵数を減らさない。

## 改善と拡張

負荷が確認された箇所から、背景/文字キャッシュ、粒子上限、変更時だけのDOM更新、探索範囲限定を小さく試す。1変更ごとに見た目、経路、入力感、セーブ互換を比較する。豪華な演出が目的なので標準設定を一律に簡素化しない。

続いて、セーブのエクスポート/インポート、素材マニフェスト、フォールバック付き音声ロード、GitHubのCIを別々に進める。公開方針が決まった段階でデプロイ設定を追加する。新ステージは依頼内容に沿って、既存8コースとセーブ互換を維持して追加する。

合格条件は既存テスト、実機の複数指入力・回転・音・一時停止復帰、ゲームオーバー、フィーバー復帰、セーブ互換。改善と呼ぶ変更には比較測定を添え、未確認の問題を解消済みと書かない。
